# Scanner prompt evaluations

These small repositories exercise ownership, false positives, severity and unchanged rescans. They cover dependency inversion, retained migrations, referenced unreachable code, boundary validation, valid-input computation errors, setup documentation, independent conventions, security test gaps, workflow injection and dummy credentials. Expected root causes are kept outside the scanned checkout.

Run `bun run eval:scanners prepare /tmp/codetend-eval-first` with a **new** destination. Each case contains a `repository/` and one JSON task per scanner with the production system instructions, message and output schema. Execute each task in a fresh scanner session with the normal read-only sandbox/tools and mount only that case's repository. Adapt the checkout path in the message to the runner's mount. Do not expose the rubric to the scanner. This command prepares tasks; it does not call a model or claim measured precision.

Collect results as an array of `{ "caseId": "domain-owned-port", "scanners": [{ "scannerId": "architecture", "result": <structured scanner result> }] }`. Run `bun run eval:scanners prepare /tmp/codetend-eval-second first-results.json` to generate unchanged-rescan tasks with the first pass's actual fingerprints and previous IDs. Add second-pass outputs as `rescan` arrays to the same result records, then run `bun run eval:scanners score results.json`.

The scorer fails on missing cases/scanners, unexpected findings, incorrect ownership/anchors, severity outside the allowed range, and rescan identity or verdict drift. Review each finding against the `rootCause` rubric as well: automated ownership/location checks cannot establish semantic correctness. Save the model, effort, token usage, commit and raw results when comparing prompt versions. Repeat paired runs to measure model variance; unit tests alone are not evidence of improved precision or recall.

Production scans now use capability-based security review for application and CI scanners, followed by conservative cross-scanner duplicate adjudication. Only independently adjudicated findings sharing inspected source anchors are consolidated; uncertain or unsupported merges retain both findings. Duplicate corrections preserve a surviving scanner/fingerprint in lifecycle notes. Checkpoints publish progress, not findings, so reviews precede lifecycle transitions and scoring. Explicit deferred prechecks preserve state and last-seen evidence. A high-confidence critical open finding caps the overall score at 39/F; security and dependency findings require confirmed exploitability for this cap. Older security findings without review evidence do not trigger the cap until reviewed again.
